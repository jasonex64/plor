# Roadmap

At the start of each session, agents report the current milestone, its status and what comes next.

## Product
This is a daily game platform, named **Plor** (human, 2026-10-18; at `plor.app`). It should feel welcoming but neutral (human, 2026-10-19). Players play the day's game, watch friends' runs live (including where each friend "died"), comment and react on the day's game, and earn cumulative points for a friends leaderboard. It's built to hold more than one game later, but it ships with one.

**Game 1: Don't Match the Host** (named Offbeat, `game_id` `offbeat`). Each day has 7 fixed, independent questions that mix concrete and abstract (e.g. "Name a day of the month", "Name something you'd bring to a potluck"). The player names an answer and must avoid the host's secret answers, which catch a slowly rising share of players through the day. Niche answers are a fair escape, and some days are harder than others. Matching ends the run, and the score is the number of questions survived. See DECISIONS.md for the answer model.

After the MVP (human, 2026-10-19; game 2 changed 2026-10-20): **game 2** (name to be decided), a substring game inspired by JKLM: given a few letters such as "cks", type a word containing them within a time limit ("rocks", "backspace"). The day's substrings are the same for everyone, and the game must never ask for something impossible or too hard like "iur" (human, 2026-10-20). Claude's suggestion: a deterministic script picks them from the dictionary, using only substrings that enough dictionary words contain, so this game needs no AI drafting (the minimum count and the time limit are human numbers). *Open:* scoring by word length, or by word rarity (a deterministic option is a licensed word-frequency list pinned in SOURCES.md, so the score is known when the player answers), and a bonus for using more different letters across the run. Use our own name and look, not JKLM's. **Game 3**, a daily word-guessing game under its own name, look and word list. Not Wordle's name or its green, yellow and gray tiles: in 2024 the New York Times sent takedown notices over exactly those, while saying it has no issue with similar games that don't infringe its trademarks or copyrighted gameplay (Fortune, 2024-03-13). Not legal advice; ask a lawyer before money is involved. **Game 4**, a word chain ("off → w___ → white → white h___ → white house"). **Game 5**, anagrams: find as many words as possible in the day's letters. **Game 6**, a word hunt: find words in a letter grid. Games 5 and 6 both have a **bonus letter**: each word that uses it earns extra points (human, 2026-10-19; the point values are human numbers for their tickets). Games 2, 3, 5 and 6 need one shared **dictionary**: a word list whose license allows use in Plor (pinned in SOURCES.md and approved by the human), with offensive words and proper nouns removed, and the server as the only judge of a valid word, so the full answer list never reaches the client. The word chain needs a separate list of two-word phrases. **Leaderboards across games:** each game has its own leaderboard, plus an overall one that adds up all games (human, 2026-10-19). Because the total adds points from different games, each game's point values (human numbers) also decide how much it weighs in the total. Pull the platform/game boundary out at game 2. Then order the rest by beta data: streaks, answer stats ("12% picked lion"), reminders, an admin UI for content, a global leaderboard (out of scope for now, human 2026-10-19), a native app wrapper, public comment moderation.

## Ideas (unscheduled)
From the human's braindump on 2026-10-20. Nothing here is scheduled or decided unless it says so. Each idea gets pulled into a milestone on purpose, with a ticket that answers *who uses it* and *what breaks without it*.

**"No suggestions while typing"** (human, 2026-10-20, recorded only as D15 on the M12 branch): the player types free text and the server matches it. This changes the answer model (DECISIONS.md: the client submits entry IDs from autocomplete, never raw text), so it needs a DECISIONS.md entry, approved by the human, before any code.

**Offbeat mechanics (human, 2026-10-20: "both", visual and mechanics; the Wind is the host, M12 D19).** Two decisions are needed, and the second must be made before the M08 ticket, because M08 writes and backfills the points ledger:
- On the last question, the wind "blows 3 answers": does that mean the last question always has exactly 3 host answers? Today the host-answer count varies by question so that difficulty (the share of players caught) rises gently (DECISIONS.md, Game 1).
- "Exponential distance" between rounds: if this changes scoring, it replaces k points per survived question k (DECISIONS.md, human-accepted 2026-10-17). If it is only visual, it goes to M12.

**Parked until there is beta data** (human, 2026-10-20: "makes sense to wait"):
- How many daily games, and whether all are always available or they rotate. Claude leans always-on, since daily games run on habit and rotation breaks it; decide with per-game retention numbers.
- How to fix a game that is much less popular than the others (needs the per-game health numbers below first).
- A feed of reactions and comments for the games a player is interested in (human: "curated feed, either direct or indirect"). Only matters from game 2.
- "Poke" a friend who hasn't played today. Goes with reminders (after the MVP); needs a notification channel and a per-friend daily cap (a human number), and it risks being annoying.
- One harder day each week for every game. An M04 content rule, once the playtest has calibrated difficulty.

**Endgame goal (human, 2026-10-20: "number one").** Puzzles for every game are created automatically, and the health of each game and question is monitored (what is doing well and what isn't, real difficulty), with the results stored so the games improve over time. For Offbeat this is M03 + M04; per-game health is new once there is more than one game. Claude's suggestion for M04, not decided: make "no repeat of a past prompt" an automatic gate, since repetition is the main long-term risk of AI drafting.
