There is one way to do each thing, and agents use exactly what is listed here.
To change a row, record the new decision, remove the old way from the code **in the same change**, and add a line to the log.

## Game 1: Don't Match the Host
- **Name and ID.** `game_id` is `offbeat`, and it's **permanent**: it's stored with every run, event, ledger row and content path. The display name "Offbeat" is branding and can change without a migration. (Human, 2026-10-18.)
- **Sudden death.** Matching the host ends the run; the points come from the questions survived (Scoring, below).
- **Fixed sequence.** Every player gets the same 7 questions in the same order each day, so friends' scores can be compared directly.
- **Independent questions, rising difficulty.** The day's questions are unrelated to each other and mix concrete ones (a clear answer set, e.g. days of the month) with abstract ones (e.g. something you'd bring to a potluck). Difficulty is the share of players the host's answers would catch. The host names 1, 1, 1, 1, 2, 2 and 3 answers on Q1 to Q7, drawn at random from the host bank, and a day's 7 questions go easiest first by expected catch rate (M13 13c, 13d). Easy and hard days are variance (human, 2026-10-24: "if we happen to have really easy or really tough days, thats just part of variance adn what will drive engagment"). The "Gentle" targets, 3, 5, 7, 10, 13, 16 and 20 caught per 100 players and about 45% finishing, replace "most players should usually finish" (human, 2026-10-24: "Gentle: 3→20%, ~45% finish"); they're a soft guide shown in the draft's summary, never aimed at ("Keep as a soft guide", "Show, never warn (Recommended)"). Catch rates are estimates until the closed beta measures them (M15; the beta is the live playtest, human, 2026-10-20). The M02 2g survey gave a first, small sample. (Human, 2026-10-18. This replaces the narrowing chain and the "question k has k host answers" rule.)
- **Timer.** Each question gives 20 seconds, from Start (question 1) or from Next after the reveal (the rest; M04 13c-4); when they run out, the run ends (human, 2026-10-21; M04 13c-2). The database is the judge: `private.question_deadline` holds the 20 seconds, the answer trigger refuses a late answer, and the status view shows the run as timed out. The client only displays the time left that the server measured. **Midnight doesn't end a run:** a run started before the reset can be played to its end after it, and its points count like any other run's, for the day it was played (human, 2026-10-22, M09 D1: "a run's points count whenever it's finished, for its own day, and a run that's never finished counts nothing"; it replaced the 2026-10-21 rule that such a score doesn't count). So no run is "abandoned" any more: a run ends with a catch, its last question, or a question's time running out, and a run left at a reveal stays in progress until the player taps Next (M04 13c-4); a reload resumes it, even after midnight ("Resume yesterday's run", human, 2026-10-21). A run left at a reveal scores nothing until the player comes back and finishes it; one never finished never scores (M09 D1).
- **Scoring:** surviving questions 1 to 7 earns 25, 50, 75, 100, 150, 250 and 350 points (human, 2026-10-21, M04 G1: points rise with each harder question in growing jumps; `POINTS_PER_QUESTION` in `tunables.ts`). It replaced k points for question k (proposed by Claude, accepted by a human, 2026-10-17). A run that ran out of time scores the questions it survived, like a caught run (human, 2026-10-22, M09 D2). **Rarity bonus** (human, 2026-10-22, M09): each survived answer also earns a bonus that's bigger the fewer players gave the same answer to that question that day, counted among the players who answered it. Each answer starts from a first guess, 40% of players giving some common answer, 40% some uncommon one and 20% some rare one, each split among the tier's members (the day's levels; M13 D5), and the counts pooled over every day of the question's category, all days equal, are blended in (M13 13c). The player sees a provisional bonus at once, pooling past days only; the final one adds the day's own answers recorded before its midnight. An answer nobody has given yet keeps nearly the full bonus ("Full bonus, as now"). Answers given after midnight earn no bonus (M09 D8). A run's bonus is always less than the points of the first question it didn't survive, so getting further always beats rarer answers; a perfect run's bonus has its own cap. So 1000 is no longer the maximum; comparing games is planned with daily percentiles (draft M16). The weights, the formula and the caps are numbers the human gives (M09 ticket, Numbers).
- **Server is authoritative.** The client never receives host answers, or anything that marks the host bank, before the player answers that question.

- **Resolving typed text** (`src/game/matching.ts`, `private.resolve_answer`). **The client sends the typed text** and the server alone turns it into a member (human, 2026-10-21; M04 13c-1): an exact name or alias after normalization first, otherwise text of 4+ letters (spaces and digits aren't letters) one typo from exactly one answer. Text that close to no answer, or to two (the server would be guessing which one), is "not in our list, try again": a free retry, logged as a miss (human, 2026-10-21). Every alias counts, scientific names included ("Yes, they count", human, 2026-10-24). A stolen letter limits what can be typed, not which names count ("Yes: letters limit typing", human, 2026-10-24); a typo is fixed only onto a name that avoids the stolen letters (G12).
- **A name on several members.** On one line of the tree it is the highest member, which covers the rest. Unrelated members ("robin") are one answer, caught if any of them is ("Caught if any meaning is", human, 2026-10-24). The stored answer is the caught one, else the most common level, else the smallest ID.
- **Catching.** A host answer catches itself and everything under it in the tree: "bear" catches "polar bear", not the reverse ("Caught: bear covers it", human, 2026-10-24). This replaces format 2's match groups and its "one level of detail per question" rule.
- **Fixed when the day starts.** A day's answers are fixed at the start of its day (midnight Pacific), or at its approval if that came later (`private.answers_as_of`): only aliases, facts and accepted extras added by then count, and only removals made after then are ignored. So a started day never changes while the base grows (human, 2026-10-24, on size: no per-day copy), and a day approved ahead picks up what was learned before it starts ("Yes, from the next day (Recommended)", M13 13b).
- **The reveal** names a thing by its main name (human, 2026-10-24).
- **Normalization** (case, whitespace, punctuation, diacritics, format characters) is applied to names when they're imported and to typed text at runtime, by `normalize` in `src/content/puzzle.ts`; nothing else is guessed.
- **Niche answers are an intended escape** (human, 2026-10-18), similar to Krillion's rare-answer play. The remaining risk is a source missing a fair answer, which the next point closes.
- **Learning from misses** (M13 13b; `private.record_miss`, `docs/milestones/M13-13b-learning-from-misses.md`). Every miss is logged with its normalized text. Once a text was typed for a category by at least 3 players, and at least 1% of the players who answered that category's questions, on any day (M13 D4), it's decided once, in this order: within a typo of a member, it waits in the audit as a typo ("Audit only"); naming a thing in the base outside the category, it's rejected and waits in the audit ("Facts win"; all of WordNet's nouns and Wikidata's places of 100,000+ people are loaded, so the base knows "Paris"); holding a word on the LDNOOBW list, it's held for the human; otherwise it becomes a new member, named the way players most often typed it, from the next day that starts. The player always sees "not in our list". The human audits on `/admin/audit`: undo an added answer, link a new or near-typo text to the member it names, accept a held one, accept a rejected one for that category alone (a rejected text isn't linked: "keep china as only the place and country for now"), or dismiss; every decision takes effect from now, and every decision that made an answer can be undone ("Yes, undo anything (Recommended)"). Nothing is deleted: removals carry `removed_at`.
