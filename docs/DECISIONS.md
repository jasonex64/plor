## Game 1: Don't Match the Host
- **Name and ID.** `game_id` is `offbeat`, and it's **permanent**: it's stored with every run, event, ledger row and content path. The display name "Offbeat" is branding and can change without a migration. (Human, 2026-10-18.)
- **Sudden death.** Matching the host ends the run, and the score is the number of questions survived.
- **Fixed sequence.** Every player gets the same 7 questions in the same order each day, so friends' scores can be compared directly.
- **Independent questions, rising difficulty.** The day's questions are unrelated to each other and mix concrete ones (a clear answer set, e.g. days of the month) with abstract ones (e.g. something you'd bring to a potluck). Question k has k host answers, so later questions eliminate more answers. Later questions use smaller answer sets, because difficulty is the host's share of the answers, not the count alone. (Human, 2026-10-18. This replaces the narrowing chain.)
- **Scoring:** surviving question k (1-based) earns k points, so a run that survives n questions scores n(n+1)/2. Abandoned runs score 0. (Formula proposed by Claude and accepted by a human, 2026-10-17. The values go in `tunables.ts`.)
- **Server is authoritative.** The client never receives host answers, or anything that marks the host bank, before the player answers that question.

### Answer model (confirmed)
| Bank | Contents | Sent to client? |
|---|---|---|
| Accepted bank | Every valid answer, including obscure ones. For an abstract question with no complete answer set (e.g. "something you'd bring to a potluck"), a curated set of reasonable answers instead (human, 2026-10-18) | Yes, as canonical entries, for autocomplete |
| Host bank | A small subset of common, typical answers | Never, and nothing marks which entries are in it |
| Host answer(s) | Picked from the host bank | Only after the player has answered that question |

- **Canonical entries.** Each entry has an ID and aliases (plurals, alternate spellings, synonyms). The client submits the entry ID, never raw text. The server rejects IDs that aren't valid for the question. Matching compares IDs.
- **Match groups.** A host answer covers more specific entries (*eagle* covers *bald eagle*). It's a match when the player's entry is the host answer itself or is in the host answer's group. **A host answer always matches itself**, so its group lists only the other entries it covers, and listing it inside its own group is a content error (human, 2026-10-18; M01 review).
- **Normalization** (case, whitespace, punctuation, diacritics) and **plural aliases** are applied when content is authored, by a deterministic step that a human reviews. Nothing is guessed at runtime.
- **Open risk:** obscure answers may be a free escape. Without a narrowing chain, nothing shrinks the answer space except each question's own size. Assess this in the M02 playtest, and a human decides any fix.
